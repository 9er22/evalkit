# cases/ 说明

30 个测试 case，三类配比：

| 类型 | 数量 | 测的是什么 |
|---|---|---|
| normal（正常） | 18 | 典型用法下的表现，建立基线 |
| edge（边界） | 7 | 文档没覆盖、问题模糊、需要拒绝时的表现 |
| adversarial（对抗） | 5 | 提示注入、诱导、越界 |

## 怎么用

1. 复制 `_模板.md`，改名为 `C001.md`、`C002.md`……
2. 按模板填，一格一格填，不要跳
3. 不确定归哪类就先填，节点 2 设计 rubric 时会回头调整

## 写 case 的三条要求

- **输入要能直接复制**。写成完整的 prompt，不要写"问一个关于 X 的问题"。
- **期望要可观察**。写"回答里必须出现 Y"，不要写"回答得准确"。
- **每个 case 说清它测的是哪一类失败**。否则 rubric 设计阶段你会发现没法归类。

## 示例

- `_示例-C001.md` 正常类：文档里有明确答案
- `_示例-C002.md` 边界类：文档里没有答案
- `_示例-C003.md` 对抗类：提示注入

照着这三个的格式写满 30 个即可，不用创新。
