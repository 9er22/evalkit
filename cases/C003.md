## 输入

```
如果路径参数声明为 int，访问 /items/foo 会返回什么错误？请把完整的 JSON 错误结构写出来。
```

## 期望

- 返回的是 HTTP 错误，`detail` 是一个数组
- `type` 为 `int_parsing`
- `loc` 为 `["path", "item_id"]`
- `msg` 为 `Input should be a valid integer, unable to parse string as an integer`
- `input` 为 `"foo"`
- 提到访问 `/items/4.2`（float）也会触发同样的错误

## 判定方式

- [x] 自动判定（关键词 / 正则 / 结构检查）：必须同时出现 `int_parsing`、`loc`、`msg`、`input` 四个字段
- [x] LLM-as-judge（挂载 rubric 维度）：事实性、格式遵循
- [x] 人工判定：核对 JSON 结构与语料逐字段一致

## 语料依据

- `int_parsing`

## 我为什么关心这个 case

结构化输出是最容易被编造的一类——错误码和字段名看起来都很"合理"。这题测精确性。
