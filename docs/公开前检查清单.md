# 公开前检查清单

> **仓库当前保持私有**（常硕 2026-09-12 裁定，不是"忘了公开"）。
> 立这份清单**不是为了现在公开**，是为了保证"真要公开的那一天"不会出现"公开之后才发现"的事故。
> 立清单的成本是一次阅读；漏掉的成本是历史已经推出去、撤不回来。

## 为什么需要它：本项目已经实证过一次

`.workbuddy/memory/` 下 5 个文件（含求职策略、认知缺口、简历注水自述、双会话角色分工）**已经进过 git 历史**。
`.gitignore` 只能挡**以后**的提交；对**已跟踪文件无效**，对**历史更无效**。

> 一句话：**"加了 .gitignore" ≠ "清干净了"。** 这两件事必须分开检查，本清单的两条命令就是分别查它们。

---

## 一、两条自检命令（只读，随时可跑）

### 命令 1：扫历史——有没有敏感文件曾经被提交过

```bash
git -c core.quotepath=false log --all --pretty=format: --name-only --diff-filter=A \
  | sed '/^$/d' | sort -u \
  | grep -E '^\.workbuddy/|^docs/求职策略-|^docs/疑问清单-|^research/(调研|岗位调研)-'
```

- **期望输出：空。** 有输出 = 该路径进过历史，**只有历史重写才能清掉**（`git rm --cached` 不够）。
- `-c core.quotepath=false` **不能省**。git 默认把非 ASCII 路径转义成 `\345\262\227...`，直接 `grep 中文` 永远匹配不到，会得到"扫过了、很干净"的**假阴性**。（写这份清单时实际踩到：漏报了 `research/岗位调研-AI辅助的产品经理.md`，加上这个参数才抓出来。）

### 命令 2：扫当前工作区——有什么还没提交 / 敏感文件是否真被忽略

```bash
git -c core.quotepath=false status --short --untracked-files=all
echo "--- 敏感文件（!! = 已被忽略，安全；?? = 漏网，先补规则）---"
git -c core.quotepath=false status --short --ignored --untracked-files=all \
  | grep -E '^(\?\?|!!).*(\.workbuddy/|求职策略|疑问清单|岗位调研|research/调研-)'
```

- **期望**：第二段里敏感文件**全部是 `!!`**。任何一条是 `??`，说明 `.gitignore` 规则漏了。
- 第一段用于**提交前自查**：看着输出再决定 `git add` 哪些，**不许 `git add -A` 一把梭**。

## 三、历史重写：登记（待执行）

**触发条件**：决定把仓库转为公开的**那一刻之前**。
**现在不做**：① 重写会改变**全部** commit 哈希，凡记过旧哈希的文档都要同步（这个代价 2026-09-12 已为"修 commit message 口径"付过一次，见 §五）；② 移除路径应与"转公开"这个动作**绑定执行**，否则在私有期内白白打乱一次哈希；③ 外部审阅冻结窗口进行中，虽然指纹算的是**文件内容**、重写不影响 `check_freeze.py` 的核对，但没有必要在窗口内多制造一次扰动。
**一次做完**：filter-repo 之前若又发现别的历史级问题（改作者、再改 message、删路径），攒着并进**同一次**重写。

> 当前待重写的历史级问题**只剩一件**：移除敏感路径。commit message 口径已于 2026-09-12 单独修正（见 §五）。

**待执行命令**（需先安装：`pip install git-filter-repo`）：

```bash
# 0. 先全量镜像备份（放仓库外，重写不可逆，备份是下限）
git clone --mirror . ../evalkit-backup.git

# 0.5 备份分支必须先处理掉：本仓库现有一条 backup/pre-msg-reword
#     （2026-09-12 filter-branch 前建的，指向重写前的旧历史）
#     filter-repo 默认重写所有 refs，但它只 rewrite 不 gc——重写后旧对象仍挂在 reflog/
#     backup 分支上，push 时虽不会带出去，本地却永远"复活"得了。
#     两种做法二选一，做完再进第 1 步：
git branch -D backup/pre-msg-reword          # 做法 A：删掉（镜像备份已在仓库外，够用）
# git filter-repo 会一并重写它 → 若保留，执行后必须确认它也落在了新历史里

# 1. 全历史移除敏感路径
#    （下面的 --message-callback 是 2026-09-12 已经修过的口径，现在是空转，
#     留着只为幂等保险；真有新的 message 级修正要并进来，改这一行。）
git filter-repo --force \
  --path .workbuddy/ --path research/岗位调研-AI辅助的产品经理.md --invert-paths \
  --message-callback 'return message.replace(b"节点3：评测报告", b"节点4：评测报告")'

# 2. filter-repo 会顺手删掉 origin（防你误推旧历史），用完加回来
git remote add origin git@github.com:9er22/evalkit.git
git push --force origin main
```

**执行后必做**：

1. **重跑命令 1，期望空输出。** 不为空 = 还有路径没清干净。
2. 所有本地克隆 / 协作者**重新 clone**（旧克隆的历史仍含敏感文件，再 push 会把它们带回来）。
3. **确认没有任何文档在记录 commit 哈希**——本仓库已统一改成"只记内容指纹 + HEAD 以 `git log` 为准"（2026-09-13 起，理由见 §五）。若发现某处还写着哈希，一并改掉，否则重写后就是一条错链。
4. 重写会改变**全部** commit 哈希。所以：**若之后还有任何历史级修正（改 message、改作者、删路径），攒到一起、在同一次 filter-repo 里做完，不要分多次。**

## 四、提交纪律（日常，不必等到公开前）

1. 提交前跑**命令 2**，看着输出再 `git add <具体文件>`；**禁止 `git add -A` / `git add .`**。
2. 新目录要入库前先自问一句：**"这个目录里会不会有私人内容？"** —— `.workbuddy/` 就是这么漏掉的。
3. 判据（常硕 2026-09-12 定）：**只提交与项目有关的文件。** 求职材料、个人处境、认知记录一律不进。
4. `.gitignore` 的改动本身也要提交，否则换个 clone 规则就丢了。
