## 第 1 部分｜GitHub 远程仓库

已定方案：**GitHub · 仓库名 `evalkit` · 私有 · 用 gh CLI 认证**。

### 1.1 装 gh

在 **PowerShell 或 CMD**（不是 Git Bash）里执行：

```powershell

```

装完**必须重开一个终端**，否则 `gh` 命令找不到。
验证：

```bash

```

### 1.2 登录 —— device flow 在这台机器上走不通，改用 PAT

**结论先说：`gh auth login --web` 别试了，两次都失败，原因已查明。**

**失败原因**：机器上有沙箱代理（`http_proxy=127.0.0.1:64394`），gh 自己的 HTTP 客户端打 `github.com/login/device` 会被挡回来，报 `502 Bad Gateway` 或 `unexpected EOF`。但 curl 走同一条代理是通的。

**更深的坑**：有人试过用 curl 手动走完 device flow、拿到 token 再喂给 gh。登录**能成功**（账号正常识别），但拿到的 `ghu_` token **权限列表是空的**（`X-OAuth-Scopes` 返回空），建仓库时报：

```
Resource not accessible by integration
```

所以 device flow 这条路拿不到 `repo` 权限，彻底不通。

**可行做法**：Personal Access Token（PAT）。

1. 打开 <https://github.com/settings/tokens/new>
2. Note 填 `evalkit`，Expiration 选 `90 days`
3. scopes 只勾 **`repo`**（勾顶层会自动选中下面所有子项）
4. Generate token，复制 `ghp_` 开头的串

然后：

```bash
export GH_TOKEN="ghp_你的token"
gh repo create evalkit --private --source=. --push
```

**不要用 `gh auth login --with-token`** —— 它硬性要求 `read:org` scope，只勾 `repo` 会报 `missing required scope 'read:org'`。走 `GH_TOKEN` 环境变量会跳过这个检查，实测单 `repo` 足够建仓库和推送。

持久化到用户环境变量（之后任何新终端都能用 gh）：

```python
import winreg
k = winreg.CreateKey(winreg.HKEY_CURRENT_USER, 'Environment')
winreg.SetValueEx(k, 'GH_TOKEN', 0, winreg.REG_SZ, 'ghp_你的token')
```

## 第 2 部分｜DeepSeek API key

### 2.1 填 key

```bash
cd /d/vibecoding/evalkit
cp .env.example .env
```

然后用编辑器打开 `.env`，把 `sk-xxx` 换成真实 key：

```

```

`.env` 已经在 `.gitignore` 里（第 9、10 行 `.env` 和 `.env.*`），**不会被提交**。提交前习惯性确认一次：

```bash
git status --short     # 不应该出现 .env
git check-ignore .env  # 输出 .env 说明已被忽略
```

## 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| `gh: command not found` | 终端没重开。winget 装完必须新开一个 |
| `gh auth login` 卡在浏览器 | 复制验证码那步超时了，重跑一次 |
| `gh repo create` 说仓库已存在 | 网页上已经建过 `evalkit` 了，改用 `gh repo set-default` 或直接 `git remote add origin https://github.com/你的用户名/evalkit.git` |
| 推送报 403 | PAT 没勾 `repo` 权限，或 `gh auth refresh -s repo` |
| runner 报 401 / 402 | key 错了，或账户余额不足 |
| runner 报 `DEEPSEEK_API_KEY not found` | `.env` 没建，或建在了别的目录 |
