### 1.2 登录 —— device flow 在这台机器上走不通，改用 PAT

**结论先说：`gh auth login --web` 别试了，两次都失败，原因已查明。**

**失败原因**：机器上有沙箱代理（`http_proxy=127.0.0.1:64394`），gh 自己的 HTTP 客户端打 `github.com/login/device` 会被挡回来，报 `502 Bad Gateway` 或 `unexpected EOF`。但 curl 走同一条代理是通的。

**更深的坑**：有人试过用 curl 手动走完 device flow、拿到 token 再喂给 gh。登录**能成功**（账号正常识别），但拿到的 `ghu_` token **权限列表是空的**（`X-OAuth-Scopes` 返回空），建仓库时报：

```
Resource not accessible by integration
```

所以 device flow 这条路拿不到 `repo` 权限，彻底不通。

**可行做法**：Personal Access Token（PAT）。

1. 打开 <https://github.com/settings/tokens/new>
2. Note 填 `evalkit`，Expiration 选 `90 days`
3. scopes 只勾 **`repo`**（勾顶层会自动选中下面所有子项）
4. Generate token，复制 `ghp_` 开头的串

然后：

```bash
export GH_TOKEN="ghp_你的token"
gh repo create evalkit --private --source=. --push
```

**不要用 `gh auth login --with-token`** —— 它硬性要求 `read:org` scope，只勾 `repo` 会报 `missing required scope 'read:org'`。走 `GH_TOKEN` 环境变量会跳过这个检查，实测单 `repo` 足够建仓库和推送。

持久化到用户环境变量（之后任何新终端都能用 gh）：

```python
import winreg
k = winreg.CreateKey(winreg.HKEY_CURRENT_USER, 'Environment')
winreg.SetValueEx(k, 'GH_TOKEN', 0, winreg.REG_SZ, 'ghp_你的token')
```

### 1.3.1 推送通道：git 的 HTTPS 在这台机器上是死的，必须走 SSH

**现象**：`git push` / `git ls-remote` 对 `github.com` 走 HTTPS 时**完全无响应**，走代理和不走代理都卡住（`timeout 30` 都等不出结果）。

**但不是网络问题**：同一时刻 `gh` 和 `curl` 都能正常访问 GitHub。说明卡死的是 git 自己的 HTTPS 通道，跟账号、token、仓库权限都无关。

（这也是为什么第一次 `gh repo create --source=. --push` 能成功——那次是 gh 自己发的推送，没走 git 的 HTTPS 通道。）

**解法**：改用 SSH。

```bash
# 1. 生成密钥
ssh-keygen -t ed25519 -C "evalkit" -f ~/.ssh/id_ed25519_evalkit -N ""

# 2. 公钥加到 GitHub —— 只能走网页：https://github.com/settings/ssh/new
#    （不能用 API：需要 admin:public_key scope，PAT 只勾了 repo）
cat ~/.ssh/id_ed25519_evalkit.pub

# 3. 写 ~/.ssh/config
# Host github.com
#   HostName github.com
#   User git
#   IdentityFile ~/.ssh/id_ed25519_evalkit
#   IdentitiesOnly yes

# 4. 验证 —— 应看到 "Hi 9er22!"
ssh -T git@github.com

# 5. 切换 remote
git remote set-url origin git@github.com:9er22/evalkit.git
git push -u origin main
```

改完之后 `git ls-remote origin` 秒回。

### 2.3 模型配置与切换（2026-09-08 核对）

模型注册表在 `src/run_eval.py` 的 `MODELS`，切换用 CLI `--model`（覆盖 .env）或改 `.env` 的 `DEEPSEEK_MODEL`：

| 别名 | 完整模型名 | 说明 |
|---|---|---|
| `v4-flash` | `deepseek-v4-flash` | **默认**。现役版本 DeepSeek-V4-Flash-0731 |
| `v4-pro` | `deepseek-v4-pro` | 现役版本 V4-Pro-0813，价格约 3 倍 |
| `v4-flash-vision` | `deepseek-v4-flash-vision-exp` | 实验版多模态 |
| `v4.1-flash-beta` | `deepseek-v4.1-flash-expires-on-0910` | ⚠ 限时内测，**2026-09-10 过期** |
| `chat` / `reasoner` | `deepseek-chat` / `deepseek-reasoner` | 已废弃别名，随时可能停用 |

来源与坑：

- **V4.1 Flash 是 2026-09-08 当天在 DeepSeek 官方群开的限时内测**，官方文档/Change Log 截至当晚都没有收录——查官方文档查不到它，要从社区消息拿模型名。新架构 + 原生多模态，计费同 v4-flash，单账号限 20 并发（正式版 2500）。实测 C001 冒烟 1.18s（v4-flash 同题 2.16s），确实快。
- **`deepseek-chat` 别在评测里用了**：官方 2026-04-24 公告废弃（原定 07-24 停用），实测 09-08 仍可调通，但它现在指向 v4-flash 非思考模式，哪天断掉分数就会"莫名"变化。
- **v4 系默认开思考模式且忽略 temperature**。本项目 temperature=0 的可复现性设定依赖显式传 `thinking: disabled`（runner 已默认这么传）。开思考：`--thinking enabled --effort low|high|max`，此时 temperature 不生效，meta.json 里记为 `null`。

```bash
python src/run_eval.py --smoke --model v4.1-flash-beta    # 内测版
python src/run_eval.py --thinking enabled --effort low    # 思考模式
```

内测版过期（09-10）后 `MODELS` 里那一条会失效报错，届时删掉即可；正式版上线后把新模型名补进注册表。

## 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| `gh: command not found` | 终端没重开；或 PATH 没写进去。用 `python -c "import winreg; ..."` 查 `HKCU\Environment` 的 Path（`reg.exe` 被沙箱拦了） |
| `gh auth login --web` 报 `502 Bad Gateway` / `unexpected EOF` | 沙箱代理挡了 gh 的 HTTP 客户端。走不通，改用 PAT（见 1.2） |
| `gh auth login --with-token` 报 `missing required scope 'read:org'` | PAT 只勾了 `repo`。**别去补 scope**，改用 `export GH_TOKEN=...` 绕过检查 |
| 建仓库报 `Resource not accessible by integration` | device flow 拿到的 `ghu_` token 权限为空。换 PAT |
| `git push` / `git ls-remote` 卡住无响应 | git 的 HTTPS 通道在这台机器上是死的。改走 SSH（见 1.3.1） |
| `gh api user/keys` 报 404 需要 `admin:public_key` | 加 SSH 公钥只能走网页 <https://github.com/settings/ssh/new> |
| `winget install` 报 `create_symlink` 后回滚 | 开发者模式没开。别重试，直接下 zip 部署（见 1.1） |
| runner 报 401 / 402 | key 错了，或账户余额不足 |
| runner 报 `DEEPSEEK_API_KEY not found` | `.env` 没建，或建在了别的目录 |
| runner 报模型不存在 / 400 invalid model | `v4.1-flash-beta` 过期了（09-10 后）。删掉注册表里那条，或换回 `v4-flash` |
| 同一批 case 分数突然变化 | 先查 `runs/<ts>/meta.json`：语料/提示/case/模型配置哪一环的 hash 变了。`deepseek-chat` 这类别名被官方悄悄换底层时 hash 不会变——所以只用显式版本号模型 |
