## 1. 为什么做这个实验

核心三问，此前只答了两个：

| | 问题 | 状态 |
|---|---|---|
| ① | 它现在好不好 | 已答：开卷 30/30、闭卷 23/30 |
| ③ | 坏在哪类问题 | 已答：闭卷 7 个失败**全部**是检索漏检导致的 B 型失败 |
| ② | **改版后是变好还是变坏** | **从未跑过** ← 本实验就是为它准备的 |

闭卷模式的设计意图就是把 RAG 的「检索」这一环补上：开卷时答案就在眼前、区分度为 0；
闭卷只注入 top-k 相关片段 + 噪声片段，失败才可能真实发生。
**既然 7 个失败全部来自检索，那"改检索"就是唯一值得做的改动。**

## 2. 根因诊断（已实测，非推测）

### 2.1 先确认因果链成立

对基准轮逐 case 交叉核对（检索命中 × 判定结论）：

- **7 个失败 = 7 个漏检**，一一对应：C001 / C002 / C006 / C010 / C012 / C013 / C015，失败类型**全是 B**；
- 全轮漏检共 **11** 个，其中 4 个（C014 / C016 / C022 / C025）**漏检但仍通过**。

→ **"命中率"是代理指标，"闭卷通过数"才是最终判据**（见 §4）。

### 2.2 根因一：跨语言断裂（主因，物理级）

- 语料是**纯英文**（FastAPI 官方文档，中文字符数 **0**）；case 提问是**中文**；
- 检索器的 `tokenize()` 产出两类 token：英文词（≥3 字符）＋ **中文二元组**，
  中文二元组**永远不可能**匹配到英文语料；
- 于是中文提问里**只有夹带的英文标识符**（`item_id`、`response_model`…）能参与匹配；
- 实测：提问中英文 token 数 = 0 的 6 个 case（C006 / C010 / C012 / C019 / C021 / C029）
  **检索结果全是空集**，其中有金标的 3 个（C006 / C010 / C012）**全部漏检 → 物理上不可能命中**。

> 一句话：**现状命中率 ≈「提问里恰好夹带了金标片段英文标识符」的比例。**
> 50% 这个数字量的是提问的措辞习惯，不是检索能力。

### 2.3 根因二：打分无长度归一化（次因）

- 现状打分 `sum(log(n / (1+df)))` —— 无 tf、**无文档长度归一化**；
- chunk 长度中位数 **841**，最长 **6766**（`response-model.md#07`，**中位数的 8 倍**）；
- 长 chunk token 多 → 常见词命中机会多 → 霸榜。实测 `response-model.md#07` 是 **11 个 case 的 top-1**；
- 典型受害者 **C001 / C002**：提问里明明有 3 个英文标识符命中金标片段，仍被长 chunk 挤出 top-3。

### 2.4 本轮新发现：基准轮有 1 个漏检 case 的金标被抽进了噪声

dry-run 复现基准时发现：**C014 的金标 chunk（`body.md#00-head`）被抽成了噪声片段**。
C014 正是「漏检但仍通过」的 4 个之一 —— 也就是说它不是"模型从常识补上了"，
而是**答案确实被注入了**（只是没被算作命中）。

- 影响：基准轮 23/30 里至少有 1 分来自这个仪器漏洞，**"漏检非必死"这条结论被削弱了一条证据**；
- 处置：本次实验把噪声口径改成固定池，并**从池里剔除该 case 的金标 chunk**（见 §5）。

## 3. 唯一变量与实验臂

### 3.1 唯一变量

**只改"选哪 3 个相关片段"**，其余一切不变：

- 注入规模**固定** `top-k=3 + noise=3`（共 6 片段）。**禁止**靠抬高 top-k 刷命中率
  ——那等于偷偷把任务变简单，对比立刻失效；
- 模型、温度、思考模式、语料、系统提示词、judge prompt、rubric **全部不动**。

### 3.2 候选改动与 dry-run 预演（只读，不调 API）

命中定义与 `run_closed_book.py` 完全一致（金标 chunk ∈ top-3，top_k=3）：

| 臂 | 改动 | 命中率 | 漏检集 |
|---|---|---|---|
| `v1` | 基准（词袋 + idf，原文查询） | **11/22 = 50.0%** ✅ 精确复现 | 11 个 |
| `v2-bridge` | **仅加术语桥**（跨语言对齐） | **19/22 = 86.4%** | C013 / C016 / C022 |
| `v2-bm25` | 仅换 BM25（长度归一化） | 14/22 = 63.6% | 7 个 |
| `v2` | 术语桥 + BM25 | 20/22 = 90.9% | C013 / C022 |

**自证**：`v1` 用**未改动的原路径**跑 dry-run，命中率与逐 case 漏检集合与基准轮**完全一致**
（11/22，C001/002/006/010/012/013/014/015/016/022/025）→ 预演可信。

**术语表的消融证据（这条最重要）**：术语表英文侧**全部取自语料自身的小节标题词表**、
不参考任何 case 的「语料依据」金标锚点；把一切贴近答案的措辞
（`不存在→missing`、`不传→missing`、`报错→error`…）**全部删掉后，命中率数字完全不变**。

> **收益全部来自「中文提问 ↔ 英文语料」的对齐本身，不是偷看失败 case 的答案。**

### 3.3 臂的裁定记录（9/16）

- 老师会话草案建议：主臂 = 术语桥，副臂 = 术语桥 + BM25，**闭卷只跑主臂一次**以控预算；
- 施工方转述的执行口径一度写成"改动 = 桥 + BM25"（两条根因都处置）；
- **常硕定稿：跑 `v2-bridge`（只加术语桥）**。
- 记录在案的理由：与"只跑一次"的预算约束一致；根因二已诊断但**本轮不处置**，
  报告须如实留一个"已知未修"项，不得事后补跑再叙事。

## 4. 成功标准（**跑之前先定死**）

| 指标 | 基准 | 目标 | 硬门槛 |
|---|---|---|---|
| 检索命中率 | 50.0% | ≥ 86% | ≥ 80% |
| 闭卷通过数 | 23/30 | ≥ 27/30 | ≥ 25/30 |

**守卫条件（全部满足才算"改善"）**

1. **不新增漏检**：新漏检集必须是旧漏检集的**子集**；
2. **开卷不回归**：若重跑开卷，须仍为 30/30；
3. **指纹不变**：语料、系统提示词、judge prompt、rubric、模型参数全部与基准轮一致；
4. **rubric v1.5 全程不动**。

**附加口径**：judge 噪声已知（同一份输出重判可能在 2↔3 之间翻转，见交叉验证 N2）
→ **通过数差异 ≥2 才当信号，±1 不作为结论依据。**

### 若未达标

**不改尺子、不改题面、不重跑碰运气。** 如实记录"此改动无效"。
——负结果同样回答三问②，而且是**更有信息量**的答案（它证明"失败不是检索的锅"）。

## 5. 仪器变更声明：噪声口径 `legacy → fixed`

这是本次实验里**除检索器之外唯一的改动**，必须单独声明，否则会被误当成处理效应。

| 口径 | 定义 | 问题 |
|---|---|---|
| `legacy`（基准轮） | 从"排除已选中的相关片段之后的剩余块"里抽 3 个 | **noise 随 picked 变** → 换了检索就等于同时换了两样东西（混淆项）；且金标可能被抽中（实测 C014 中招） |
| `fixed`（本次） | 固定池，只依赖 case id；池里**剔除该 case 的金标 chunk** | 两臂噪声完全一致；金标永不作噪声 → "漏检"才真的是漏检 |

**对可比性的影响方向**：`fixed` 让"漏检"的 case 拿不到金标，即**对被测臂更严格**。
所以若新臂仍达标，结论是**稳健**的（不是靠仪器放松换来的）。
反过来，基准轮的 23/30 里含有 1 分来自 `legacy` 的泄漏（C014）——这一点在报告里如实标注。

## 8. 已知残留与风险（提前声明）

1. **C013**：金标锚点是 `class Item(BaseModel):`，落在"教程第一步（import）"，
   而问题要的是"完整代码 + 哪些字段必填"。**这更像 case 锚点设计问题，不是检索问题。**
   本实验不解它，如实记为残留。
2. **C022**：金标片段仅 243 字符；基准轮里"漏检仍通过"。
3. **根因二未处置**：本轮只加术语桥，长 chunk 霸榜（`response-model.md#07`）**依旧存在**。
   BM25 已实现在 `src/retrieval.py` 里但**不启用**，其独立效果只作为 dry-run 预演记录
   （单独 14/22、叠加 20/22），**不作为本轮结论**。
4. **judge 噪声**：通过数差异 ≥2 才当信号（见 §4）。
5. **改进的是"检索层"，不是"模型层/尺子层"**：命中率上来后闭卷会趋近开卷（这是预期的），
   报告须讲清剩余失败才真正暴露后两者的问题。
