# rubrics/ 说明

这个目录是整个项目最值钱的部分——**代码可以粗糙，标准不能含糊**。

## 两条硬要求

### 1. 每档必须写具体描述

❌ 错误写法："事实性：好 / 一般 / 差"
✅ 正确写法："2 分 = 主要事实正确，但有一处次要细节在文档中找不到依据"

判断标准：**换一个人来打分，能不能打出差不多的分**。如果两个人能给同一个输出差两分，说明这档写得不够具体。

### 2. 必须留下修改痕迹

流程是：让 AI 生成第一版 rubric → **你来改** → 记录改了什么、为什么。

`_初版草案-待改.md` 是 AI 给的起点。`修改记录.md` 记你改了哪些地方。

**作品集里最值钱的就是这份修改记录**——它证明的不是"你会写 rubric"，是"你能看出 AI 写的 rubric 哪里不对"。这正是「AI 辅助的 PM」要证明的能力。

## 维度从哪来

- 通用维度：事实性、有用性、格式遵循、拒绝是否恰当
- **你自己那一条**：来自 `research/亲历_标准不一致.md` 的 Q4——那次返工里，最该被提前发现的是什么
- 被测对象特有的维度：节点 1 定完 case 之后再补
