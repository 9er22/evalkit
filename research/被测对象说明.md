# 被测对象说明

## 1. 被测的是什么

一个**最小形态的文档问答应用**：把一份固定语料整体塞进 prompt，然后向模型提问，模型只能依据语料回答。

| 项 | 设置 |
|---|---|
| 应用形态 | 全文注入式文档问答（**不做检索**） |
| 模型 | DeepSeek API `deepseek-chat` |
| 温度 | `temperature=0` |
| 系统提示 | 固定，见 `cases/_system-prompt.md` |
| 单次成本 | 30 个 case 跑一轮约几毛钱量级 |

**备选（如果没有 API key）**：豆包 / Kimi 网页版。把同一份 `CORPUS.md` 粘进对话框，逐个问 30 个 case，手动记录输出。
代价：不能脚本化，节点 3 的批量跑测要改成手动，且每次结果不保证完全一致。

### 为什么"全文注入、不做检索"

50,917 字符（约 1.3 万 token）的语料，单次完全放得下。不做检索有三个好处：

1. **失败分类里不会混入"检索失败"**。检索挂了和模型答错了是两回事，混在一起就没法定位问题。
2. **消掉 rubric 初版自己列的一个毛病**。初版草案说"没区分'文档里没有'和'文档里有但 AI 没检索到'"——全文注入之后，这个区分自动消失了。
3. **可复现性只依赖两件事**：固定语料 + `temperature=0`。少一个变量少一处不可控。

代价是它不像真实生产系统（真实系统都要检索）。这是刻意的取舍：我们评的是**生成质量**，不是检索质量。

## 2. 语料是什么、怎么固定

| 项 | 值 |
|---|---|
| 来源 | FastAPI 官方教程，GitHub `fastapi/fastapi` |
| **固定 commit** | `50113da16fec53b66b80d75e80a89296de4fa5a5` |
| 取用页面 | `docs/en/docs/tutorial/` 下的 `path-params`、`query-params`、`body`、`response-model` |
| 展开的外部代码 | 28 个 `docs_src/*.py` 文件 |
| 合并产物 | `research/corpus/CORPUS.md`，50,917 字符 |
| 生成脚本 | `src/fetch_corpus.py`（可重跑，换 commit 用 `--sha`） |

**为什么要展开 include**：FastAPI 的文档源码用 `{* ../../docs_src/xxx.py hl[3] *}` 引用外部 Python 文件，代码块根本不在 markdown 里。不展开的话，"答案在文档里"的 case 会变成"文档里其实没有"——评测还没跑就已经失效。

**为什么固定 commit**：语料在变，评测结果就不可复现。我们 rubric 里有「标准版本可追溯」这一维，语料自己必须先做到可追溯，否则是自相矛盾。

### 这份语料**没有**覆盖什么（重要）

设计 case 时先确认过一遍。以下内容**不在**语料里，问了就是"文档未覆盖"：

- `Query()` / `Path()` 的额外校验（`min_length`、`ge`、`le` 等）——在别的页面
- `status_code` 与自定义状态码——在别的页面
- 文件上传、错误处理（HTTPException）、依赖注入、中间件、CORS

这些正好用来出**边界类 case**：看被测应用会不会承认"文档没写"，还是硬编一个答案。

## 3. 为什么选它（对照三条硬标准）

| 标准 | 是否满足 | 说明 |
|---|---|---|
| **零成本或极低成本** | ✅ | 一轮 30 个 case 约几毛钱；无 key 时可退到网页版，零成本 |
| **可复现** | ✅ | 固定 commit 的语料 + `temperature=0` + 固定系统提示 |
| **事实可判定** | ✅ | 答案在不在 `CORPUS.md` 里，grep 一下就知道 |

另外两条来自决策记录：

- **不绑定任何行业**（D1 的教训）。FastAPI 是通用技术文档，不会给作品集贴行业标签。
- 30 个 case 半小时能跑完，方便迭代 rubric。

## 5. 跑测脚本

`src/run_eval.py`，零第三方依赖（只用标准库），换机器不用装包。

```bash
python src/run_eval.py --smoke            # 只跑 C001，验证链路
python src/run_eval.py                    # 全量 30 个 case
```

每轮产物落在 `runs/<时间戳>/`：`meta.json` 记录本轮的**标准版本快照**（语料 sha256、系统提示 sha256、每个 case 文件的 sha256），`raw/` 下是每个 case 的结构化结果和人可读的问答对。

这份快照是 rubric「标准版本可追溯」这一维的落地——将来分数变了，能查清是语料、提示、还是 case 哪一环动的。
