**问** 文档推荐用 response_model_include / response_model_exclude 来隐藏字段吗？

**答**

不推荐。文档明确说这两个参数只是"quick shortcut"（快捷方式），并给出了 tip：

> But it is still recommended to use the ideas above, using multiple classes, instead of these parameters.

也就是说，文档更推荐用多个 Pydantic 模型类（比如上面提到的思路）来实现字段的包含/排除，而不是用 `response_model_include` / `response_model_exclude`。

文档给出的理由是：即使你用 `response_model_include` 或 `response_model_exclude` 省略了某些属性，应用 OpenAPI（以及文档）里生成的 JSON Schema 仍然是完整模型的 schema。文档还提到这一点同样适用于行为类似的 `response_model_by_alias`。

补充说明这两个参数的用法（依据文档）：它们是 *path operation decorator* 的参数，接收一个 `set` of `str`，即要包含（其余省略）或要排除（其余包含）的属性名。如果写成 `list` 或 `tuple`，FastAPI 也会自动转换成 `set`，同样能正常工作。
