**问** response_model 应该写在哪里？能写在路径操作函数的参数里吗？

**答**

根据这份文档，`response_model` 是写在**路径操作装饰器（path operation decorator）的参数**里，不是写在路径操作函数的参数里。

文档中的示例都是这种形式：

```python
@app.post("/user/", response_model=UserOut)
async def create_user(user: UserIn) -> Any:
    return user
```

```python
@app.get("/items/{item_id}", response_model=Item, response_model_exclude_unset=True)
async def read_item(item_id: str):
    return items[item_id]
```

文档里把它称为“the *path operation decorator* parameter `response_model`”（路径操作装饰器的参数），并且 Recap 里也写的是“Use the *path operation decorator's* parameter `response_model`”。

关于“能不能写在路径操作函数的参数里”，这份文档没有讲到这种用法，也没有给出任何把 `response_model` 作为函数参数（比如 `async def create_user(user: UserIn, response_model=...)`）的示例。文档只提到另一种替代做法：用函数的**返回类型注解**（return type annotation）来声明输出模型，例如：

```python
@app.post("/user/")
async def create_user(user: UserIn) -> BaseUser:
    return user
```

但文档也说明，当输入模型和输出模型是两个不同的类时，用返回类型注解会让编辑器和工具报类型错误，所以那种情况下必须用 `response_model` 参数。
