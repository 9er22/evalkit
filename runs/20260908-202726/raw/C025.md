# C025（edge）

**问** 我的路径操作函数直接返回一个数据库对象（不是 Pydantic 类型），会发生什么？怎么解决？

**答**

根据文档，如果你的路径操作函数直接返回一个数据库对象（不是 Pydantic 类型），并且你在函数上做了返回类型注解，FastAPI 会尝试根据该类型注解创建一个 Pydantic 响应模型，但会失败。

文档中明确提到：

> 但当你返回一些其他任意的对象，它不是有效的 Pydantic 类型（例如一个数据库对象），并且你在函数中这样注解它，FastAPI 会尝试从该类型注解创建一个 Pydantic 响应模型，并且会失败。

**解决方案**：

1. **使用 `response_model` 参数**：在路径操作装饰器中声明 `response_model`，指定一个 Pydantic 模型。这样 FastAPI 会使用该模型进行数据文档、验证、过滤等，而不会尝试从返回类型注解创建模型。例如：

```python
@app.post("/items/", response_model=Item)
async def create_item(item: Item) -> Any:
    return item  # 这里可以返回数据库对象
```

2. **禁用响应模型**：如果你不想让 FastAPI 做数据验证、文档、过滤等，可以设置 `response_model=None`。这样你可以保留任意的返回类型注解，而不会影响 FastAPI 应用。例如：

```python
@app.get("/portal", response_model=None)
async def get_portal(teleport: bool = False) -> Response | dict:
    ...
```

文档还提到，如果返回类型注解是 `Response` 类或其子类（如 `RedirectResponse`、`JSONResponse`），FastAPI 会自动处理，不会尝试创建 Pydantic 响应模型。
