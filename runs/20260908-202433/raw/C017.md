# C017（normal）

**问** 输入模型里含有明文 password，怎么保证响应里不把它返回给客户端？

**答**

根据文档，有两种做法可以保证响应里不返回明文 password：

## 方法一：单独定义一个不含 password 的输出模型，用 `response_model` 声明

文档中的例子是：输入模型 `UserIn` 含有 `password`，输出模型 `UserOut` 不含 `password`，然后在路径操作装饰器里用 `response_model=UserOut`：

```python
from typing import Any

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


class UserOut(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


@app.post("/user/", response_model=UserOut)
async def create_user(user: UserIn) -> Any:
    return user
```

文档说明：即使路径操作函数返回的是包含 password 的同一个输入用户对象，因为 `response_model` 声明为 `UserOut`（不含 password），**FastAPI 会用 Pydantic 过滤掉所有未在输出模型中声明的数据**。

文档还特别提醒：因为两个模型不同，如果直接把函数返回类型标注为 `UserOut`，编辑器和工具会报类型错误，所以这种情况下要用 `response_model` 参数来声明。

## 方法二：用类继承 + 返回类型标注

文档还介绍了用继承的方式，既能获得编辑器的类型支持，又能让 FastAPI 过滤数据：

```python
from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class BaseUser(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


class UserIn(BaseUser):
    password: str


@app.post("/user/")
async def create_user(user: UserIn) -> BaseUser:
    return user
```

这里 `UserIn` 继承自 `BaseUser` 并额外加了 `password`，函数返回类型标注为 `BaseUser`。文档解释：FastAPI 会看返回类型，确保返回的数据**只包含**该类型中声明的字段，从而过滤掉 password。

## 文档中的安全警告

文档明确警告：**永远不要存储用户的明文密码，也不要像这样在响应中发送它**，除非你清楚所有注意事项并且知道自己在做什么。

---

补充说明：文档还提到 `response_model_exclude` 这类参数可以排除某些字段，但文档建议优先使用上面"多个类"的方式，因为用 `response_model_exclude` 时 OpenAPI 生成的 JSON Schema 仍然是完整模型的。
