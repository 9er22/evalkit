# C025（edge）

**问** 我的路径操作函数直接返回一个数据库对象（不是 Pydantic 类型），会发生什么？怎么解决？

**答**

根据文档，分两种情况：

## 1. 如果你给函数加了返回类型注解

文档在 "Invalid Return Type Annotations" 一节明确说明：

> But when you return some other arbitrary object that is not a valid Pydantic type (e.g. a database object) and you annotate it like that in the function, FastAPI will try to create a Pydantic response model from that type annotation, and will fail.

也就是说，如果你返回一个数据库对象（不是有效的 Pydantic 类型）**并且**在函数上加了该类型的返回注解，FastAPI 会尝试从该类型注解创建 Pydantic 响应模型，然后**失败**（文档中标注为 💥）。

## 2. 解决办法

文档给出了几种方案：

### 方案 A：使用 `response_model` 参数

文档在 "`response_model` Parameter" 一节说明，你可以**返回一个字典或数据库对象，但把它声明为 Pydantic 模型**：

> For example, you could want to **return a dictionary** or a database object, but **declare it as a Pydantic model**. This way the Pydantic model would do all the data documentation, validation, etc. for the object that you returned (e.g. a dictionary or database object).

此时把函数返回类型注解为 `Any`，用 `response_model` 来声明响应模型：

```python
@app.post("/items/", response_model=Item)
async def create_item(item: Item) -> Any:
    return item
```

### 方案 B：设置 `response_model=None` 禁用响应模型

文档在 "Disable Response Model" 一节说明，如果你不想让 FastAPI 做默认的数据验证、文档、过滤等，可以设置 `response_model=None`：

> In this case, you can disable the response model generation by setting `response_model=None`:
> This will make FastAPI skip the response model generation and that way you can have any return type annotations you need without it affecting your FastAPI application.

```python
@app.get("/portal", response_model=None)
async def get_portal(teleport: bool = False) -> Response | dict:
    ...
```

---

**小结**：直接返回数据库对象本身没问题，问题出在**返回类型注解**上。要么用 `response_model` 声明一个 Pydantic 模型（推荐，能获得验证、文档和过滤），要么用 `response_model=None` 完全禁用响应模型生成。
