**问** 我的路径操作函数直接返回一个数据库对象（不是 Pydantic 类型），会发生什么？怎么解决？

**答**

根据文档，会发生以下情况：

**会发生什么**

如果你返回一个不是有效 Pydantic 类型的任意对象（例如数据库对象），并且在函数上做了返回类型注解，FastAPI 会尝试从该类型注解创建 Pydantic 响应模型，然后**失败**（文档原文："FastAPI will try to create a Pydantic response model from that type annotation, and will fail"）。

文档还举了一个类似的失败例子：如果返回类型注解是 `Response | dict` 这样的联合类型（union），其中包含非 Pydantic 类型，也会失败 💥。

**怎么解决**

文档给出的解决方法是：设置 `response_model=None` 来禁用响应模型生成。

```python
@app.get("/portal", response_model=None)
async def get_portal(teleport: bool = False) -> Response | dict:
    if teleport:
        return RedirectResponse(url="https://www.youtube.com/watch?v=dQw4w9WgXcQ")
    return {"message": "Here's your interdimensional portal."}
```

文档说明：这样会让 FastAPI 跳过响应模型生成，从而你可以保留任何需要的返回类型注解（以获得编辑器、mypy 等工具的支持），而不会影响 FastAPI 应用。

需要注意的是，这样做也就放弃了 FastAPI 默认的数据验证、文档、过滤等功能。

（依据：片段 5/6，docs/en/docs/tutorial/response-model.md 的 "Invalid Return Type Annotations" 和 "Disable Response Model" 小节。）
