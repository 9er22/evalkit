**问** 输入模型里含有明文 password，怎么保证响应里不把它返回给客户端？

**答**

根据文档，有两种做法可以保证响应里不返回明文 password：

**方法一：单独定义一个不含 password 的输出模型，用 `response_model` 参数指定**

文档（片段 2/6）给出的例子中，`UserIn` 含 `password`，而 `UserOut` 不含：

```python
class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


class UserOut(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


@app.post("/user/", response_model=UserOut)
async def create_user(user: UserIn) -> Any:
    return user
```

即使函数返回的是含 password 的输入对象，FastAPI 也会用 Pydantic 过滤掉所有未在输出模型中声明的数据。文档特别说明：因为两个模型不同，如果直接把返回类型标注为 `UserOut`，编辑器和工具会报类型错误，所以这里必须用 `response_model` 参数声明。

**方法二：用继承 + 返回类型标注**

文档（片段 3/6）指出，在大多数只想过滤/移除部分数据的场景下，可以用类继承来同时获得类型标注支持和数据过滤：

```python
class BaseUser(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


class UserIn(BaseUser):
    password: str


@app.post("/user/")
async def create_user(user: UserIn) -> BaseUser:
    return user
```

`UserIn` 继承 `BaseUser` 并加上 `password`，返回类型标注为 `BaseUser`。类型上 `UserIn` 是 `BaseUser` 的子类，所以编辑器和 mypy 不会报错；而 FastAPI 会确保返回的数据只包含 `BaseUser` 中声明的字段，从而过滤掉 password。

**文档的警告**

片段 6/6 明确警告：不要在生产环境用同一个模型同时声明输入和输出（那样会把密码原样返回给客户端），并且"Never store the plain password of a user or send it in a response like this, unless you know all the caveats and you know what you are doing."
