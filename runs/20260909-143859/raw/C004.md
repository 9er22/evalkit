# C004（normal）

**问** 同时有 /users/me 和 /users/{user_id} 两个路径操作，声明顺序应该怎么排？写反了会发生什么？

**答**

应该把 `/users/me` 声明在 `/users/{user_id}` **之前**。

依据文档 "Order matters" 一节：

> Because *path operations* are evaluated in order, you need to make sure that the path for `/users/me` is declared before the one for `/users/{user_id}`

文档给出的正确写法：

```python
@app.get("/users/me")
async def read_user_me():
    return {"user_id": "the current user"}


@app.get("/users/{user_id}")
async def read_user(user_id: str):
    return {"user_id": user_id}
```

如果写反了（把 `/users/{user_id}` 放在前面），会发生什么？文档原文：

> Otherwise, the path for `/users/{user_id}` would match also for `/users/me`, "thinking" that it's receiving a parameter `user_id` with a value of `"me"`.

也就是说，`/users/{user_id}` 会先匹配到 `/users/me` 这个请求，把它当成 `user_id="me"` 来处理，导致 `/users/me` 这个路径操作永远不会被命中。

另外文档还提到一个相关点：不能重复定义同一个路径操作（例如两个 `@app.get("/users")`），因为路径先匹配到的那个会一直被使用。
